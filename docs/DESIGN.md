## 확정된 스택

Flask + Jinja SSR + Ajax(JSON) + **WebSocket(채팅·presence, 라이브러리 미정)** +
MongoDB + Bootstrap(CDN) + JWT(httpOnly 쿠키). 배포는 AWS EC2(추후).

## 핵심 설계 결정

- **카드 = 물품 상세 입구**: 홈 피드 카드를 누르면 물품 상세(`/items/<id>`)가 열린다.
  상세는 사진·제목·가격·유형·상태·판매자(이름·소속)를 보여주고, '채팅 바로가기'가
  1:1 채팅방을 연다. 판매자 본인 글이면 상세에 **삭제 버튼 + 거래완료 토글**이 붙는다.
- **홈 피드 페이지네이션 (v6)**: 페이지당 최대 20개 + 하단 페이지 번호. 한 페이지에
  이미지가 무한정 쌓여 생기는 로딩 부담을 줄인다.
- **방은 (글, 구매자) 조합당 1개** — 같은 글을 다시 눌러도 기존 방을 재사용한다.
  판매자는 그 글의 첫 방으로 가고, 채팅 화면 하단의 페이지네이션(1·2·3…)으로
  구매자별 방을 오간다.
- **채팅은 WebSocket (v6)**: 3초 폴링을 폐기하고 방마다 실시간 연결. 같은 연결로
  상대가 방에 들어와 있는지(presence)도 표시한다. 이벤트 계약은 `API.md` §3,
  라이브러리는 미정.
- **거래 상태 = ON/OFF 토글 (v6)**: `판매중 ⇄ 거래완료` 양방향, 판매자 단독.
  완료 글은 피드에서 '완료' 뱃지 + 사진 흑백 필터. 예약중 없음.
- **거래 유형 3종**: 판매 / 나눔 / 교환("아무거나" 또는 원하는 물건 직접 입력).
- **회원가입 소속 4종 (v6)**: `SW-AI LAB` · `GAME LAB` · `GAME TECH LAB` ·
  `코치 및 운영진`. 기수(12·13·14기) 선택을 대체한다.
- **검색 (v6, P0로 격상)**: 헤더의 검색 폼 → `GET /search?q=`가 items 제목을 DB에서
  부분일치 검색. 담당 A. 판매자 이름 검색 등 확장 범위는 미정.
- **결제**: PG 없음. **계좌번호를 다루는 UI를 두지 않는다.** 계좌가 필요하면
  당사자가 채팅 메시지로 직접 주고받는다 (§ 잘라낸 것 참조).
- **내비게이션**: 햄버거 → offcanvas 사이드바 5항목
  (Home · Community · 채팅목록 · 거래내역 · 로그아웃). navbar: 검색 폼(P0) + 말풍선
  아이콘(`/chats` 링크). 안 읽음 뱃지는 P1.
- **본인 글 카드 클릭** → 구매자와 똑같이 물품 상세로 간다. 내 글을 한눈에 보는
  자리는 거래내역(판매 탭). 마이페이지 없음.
- **SSR/Ajax/WS 경계**: 페이지 이동은 전부 SSR, Ajax는 로그인·완료 토글(+P1·P2:
  뱃지·찜·댓글), 실시간은 WebSocket 하나.

## 역할 (v6 회의 확정 — 상세는 `ARCHITECTURE.md` §6)

- **A**: 인증(로그인·가입·로그아웃) + 헤더(검색 포함)·사이드바 + 거래내역·커뮤니티 — 영역 풀스택.
- **B**: 메인 기능(피드·작성·상세·채팅)의 프론트엔드.
- **C**: 같은 메인 기능의 백엔드(라우트·WebSocket 서버).

## 우선순위

- **P0**: 인증(JWT, 소속 4종) · 거래 글 작성/삭제(사진 1장) · 홈 피드(그리드 +
  페이지네이션) · 검색 · 카드 → 물품 상세 → 1:1 채팅(WebSocket + presence) ·
  거래완료 토글(+완료 흑백 표시)
- **P1**: 거래내역 구매 탭 · 글 수정 · 안 읽음 뱃지 · 나눔/교환 필드 분기
- **P2**: 커뮤니티 전체(담당 A 확정, 우선순위 격상 여부는 미결) · 유형 필터 · 찜
