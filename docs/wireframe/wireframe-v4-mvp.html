크래프톤 당근 · 와이어프레임 v4 (MVP)

아고라 제거판 — 카드 클릭이 곧 1:1 채팅. 상태 2단계(판매중 → 판매완료). Flask + Jinja SSR + Ajax + MongoDB + Bootstrap.

화면 지도

구현 우선순위

  • P0 (표시 없음) — 이것만 되면 시연 성립: 인증 · 거래 글 작성/삭제(사진 1장) · 홈 피드 · 카드 → 물건 상세 → 1:1 채팅(폴링) · 판매완료(판매자 단독)
  • P1 코어 완성 후: 거래내역 구매 탭 · 글 수정 · 안 읽음 뱃지 · 나눔/교환 분기
  • P2 시간이 남으면: 커뮤니티 전체 · 검색 · 필터 · 찜

범례

  • SSR 화면 전환 — Jinja가 새 페이지를 렌더링해요. URL 표시줄이 함께 바뀌어요.
  • AJAX 제자리 갱신 — 찜 · 댓글 · 채팅 폴링 · 상태 전환.
  • offcanvas 분홍 태그 = 대응하는 Bootstrap 컴포넌트 이름.
  • 보라 손글씨 는 구현 메모예요. 화면 이동 시 아래 메모가 바뀌어요.

이 화면의 메모

    부록 — 팀 회의 안건 2건
    1. JWT 보관 위치 (추천: httpOnly 쿠키)

    Jinja SSR에서는 브라우저가 매 요청에 쿠키를 자동 첨부하므로 페이지 렌더링과 자연스럽게 맞물리고, XSS로 토큰을 탈취당하지 않아요. localStorage + Authorization 헤더 방식은 일반 페이지 이동에 헤더를 붙일 수 없어서 SSR과 충돌해요.

    2. SSR / Ajax 경계 (추천: 아래 규칙)

    페이지 이동(목록 → 채팅 화면 → 작성)은 전부 SSR 페이지 전환으로, Ajax는 찜 토글 · 댓글 등록 · 채팅 송수신(폴링) · 판매완료 전환 네 곳에만 써요.

    부록 — Bootstrap 도입 메모
    CDN 두 줄이면 끝

    bootstrap.min.css + bootstrap.bundle.min.js (offcanvas는 JS 번들 필수, Popper 포함). 빌드 도구 불필요 — Jinja base.html의 head에 한 번만.

    이 와이어프레임의 진짜 Bootstrap 파일 여부

    Artifact 보안 정책상 외부 CDN을 못 불러와서 룩은 수제 재현이에요. 구조와 분홍 태그가 실제 컴포넌트와 1:1로 대응하니, 구현 시 해당 컴포넌트를 그대로 쓰면 같은 화면이 나와요.

    그리드 비용

    3열↔1열 반응형은 row-cols-1 row-cols-md-3 클래스 하나예요. 위의 데스크톱/모바일 버튼으로 직접 확인해 보세요.

    테마는 기본값 유지

    기본 파랑 테마 그대로 + 색 변수 최소 수정. 커스텀 CSS는 2박 3일의 함정이에요.

    부록 — 잘라낸 것 (기록용)
    아고라 (공개 협상 스레드) — 2026-08-24 MVP 피벗

    글별 공개 협상 + 판매자 확정 버튼 구조를 통째로 제거. 구매자-판매자 사이의 결정 레이어를 하나 줄이고, 데이터 모델을 "글 + 1:1 방 + 메시지"로 축소. 아이디어는 확장 후보로 보존.

    "예약중" 상태 · 계좌 안내 modal · 계좌 입력란

    확정 단계가 사라지며 예약중도 함께 제거(판매중 → 판매완료 2단계). 계좌를 다루는 UI는 v5에서 전부 없앴다 — 개인 금융정보를 화면에 상시 띄우고 복사시키는 구조 자체가 위험해서, items.account 필드까지 삭제했다. 계좌는 당사자끼리 채팅 메시지로 주고받는다.

    제안 카드 (금액 조절 오퍼 UI)

    제안 데이터 모델 + 수락 로직 비용으로 이전 판에서 제외. 아고라 제거로 자연 소멸.
