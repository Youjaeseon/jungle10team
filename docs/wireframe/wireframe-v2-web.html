크래프톤 당근 · 와이어프레임 v2

웹페이지 UI 개편판 — 햄버거 + offcanvas 사이드바, Bootstrap 문법, 아고라의 홈 통합. Flask + Jinja SSR + Ajax + MongoDB.

화면 지도

범례

  • SSR 화면 전환 — Jinja가 새 페이지를 렌더링해요. 위 URL 표시줄이 함께 바뀌어요.
  • AJAX 제자리 갱신 — 찜 · 댓글 · 채팅 폴링 · 상태 전환.
  • ★여유 필수가 아닌 기능이에요.
  • offcanvas 분홍 태그 = 대응하는 Bootstrap 컴포넌트 이름. 공식 문서에서 그 이름을 찾으면 돼요.
  • 보라 손글씨 는 구현 메모예요. 화면 이동 시 아래 메모가 바뀌어요.

이 화면의 메모

    부록 — 팀 회의 안건 2건
    1. JWT 보관 위치 (추천: httpOnly 쿠키)

    Jinja SSR에서는 브라우저가 매 요청에 쿠키를 자동 첨부하므로 페이지 렌더링과 자연스럽게 맞물리고, XSS로 토큰을 탈취당하지 않아요. localStorage + Authorization 헤더 방식은 일반 페이지 이동에 헤더를 붙일 수 없어서 SSR과 충돌해요.

    2. SSR / Ajax 경계 (추천: 아래 규칙)

    페이지 이동(목록 → 상세 → 작성)은 전부 SSR 페이지 전환으로, Ajax는 찜 토글 · 댓글 등록 · 채팅 송수신(폴링) · 거래 상태 전환 네 곳에만 써요.

    부록 — Bootstrap 도입 메모
    CDN 두 줄이면 끝

    bootstrap.min.css + bootstrap.bundle.min.js (offcanvas·modal은 JS 번들 필수, Popper 포함). 빌드 도구 불필요 — Jinja base.html의 head에 한 번만.

    이 와이어프레임의 진짜 Bootstrap 파일 여부

    Artifact 보안 정책상 외부 CDN을 못 불러와서 룩은 수제 재현이에요. 대신 구조와 분홍 태그가 실제 컴포넌트와 1:1로 대응하니, 구현 시 해당 컴포넌트를 그대로 쓰면 같은 화면이 나와요.

    그리드 비용

    3열↔1열 반응형은 row-cols-1 row-cols-md-3 클래스 하나예요. 위의 데스크톱/모바일 버튼으로 직접 확인해 보세요 — 별도 구현이 아니에요.

    테마는 기본값 유지

    기본 파랑 테마 그대로 + 색 변수 최소 수정. 커스텀 CSS는 2박 3일의 함정이에요.
